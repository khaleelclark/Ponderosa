# Security policy

## Supported versions

`v1.0.0-beta.1`, published on 16 October 2026, is the first public beta.
Earlier builds in the private repository are historical candidates.

| Version | Security support |
| --- | --- |
| Most recent officially released public beta | Target for security fixes; currently `v1.0.0-beta.1`. |
| Earlier betas and private builds | Reports welcome; fixes and backports are not promised. |

Updating to the latest public beta may be necessary. No long-term support
period is committed.

## Report a vulnerability privately

On the [Ponderosa release repository](https://github.com/khaleelclark/Ponderosa/security/advisories), open **Security →
Advisories → Report a vulnerability** to submit a private report. See
[GitHub's reporting instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).

The repository is public. GitHub's repository API confirmed private vulnerability
reporting was enabled on 19 October 2026.

**Do not disclose suspected vulnerabilities, exploit details, credentials, or
private logs in public issues or discussions.** If the reporting option is
unavailable, keep the details private. An approved fallback private contact has
not yet been designated.

A useful report includes:

- The affected Ponderosa version or commit.
- Your operating system and version, installation method, and relevant browser
  or provider details.
- A description of the problem and its potential impact.
- Reproduction steps or a minimal proof of concept using systems and data you
  have permission to test.
- Relevant log excerpts with secrets and private content removed.

Do not attach credentials, browser profiles, provider login directories, or
complete private data archives. Describe any exposed secret without including
the secret itself.

## What to expect

Khaleel Clark reviews reports, assesses affected versions and impact, and may
ask for more information. Keep follow-up communication in the private report.
Fixes, mitigations, and disclosure timing are discussed case by case, with the
aim of helping affected users before detailed public disclosure.

No response deadline, fix date, bounty, or guaranteed resolution is promised.
