# Serial generation-one destination source

This is source assembly, not executable qualification. The bound is one manual
standalone owner, one serial resource, ASYNC/SYNC, an exact failed generation-zero
attempt, automatic fresh-context retry with maxAttempts=2, and one current issued
generation-one opening. Existing generation-zero/called-tree/group paths retain
their defaults. EXIT, local parallel retry admission, generations beyond one,
manual recovery, missing preupgrade evidence, secrets, artifacts and unknown
native/provider/effect outcomes remain refused.

The actual precleanup producer must have fenced, drained, sealed and retired
generation zero while the original identities survived. `generationOneEvidence`
reads `readGenerationExitCapture`, its immutable intake/provider/native/package
proof and exact `resource-generation-retired:<step>:0` journal. It binds the full
retired resource, members, context, operations, failed Request result, old failed
attempt and prospective retry attempt identities, configuration and pins. Missing
or changed evidence refuses. No old Chat is reconstructed or queried for current
graph authority.

The current selected cut explicitly excludes only that proven retired attempt.
The original full selected bytes remain under `generationRetry.originalSelected`.
`captureGenerationOneHost` captures ONLY actual current roots; the known retained
old context is separately checked and excluded from current contexts. A changed
or extra unknown context refuses. Only current Chat/Agent/Request identities enter
package capture, fresh maps, imports and the canonical graph writer.

The existing serial replay receives both exact host frames for validation only.
It validates the original resource opening against the old resource, the exact
failed result, fresh retry scheduling, exhaustive retirement audit prefix, and
new generation opening against the current resource. This validation-only union
is never passed to destination reserve/write. Ordinary rewind remains refused.

`GET .../resources/:stepId/generation-one-preview` returns `reviewHash`,
`historicalReviewHash`, and exact server-derived `historicalPartition` selection.
POST `issued-checkpoint` for expectedGeneration=1 requires expectedReviewHash.
Capture/seal preserve current full-tree/frontier/host CAS through the existing
package engine's synchronous owner callback. Existing issued status plus bounded
`generation-one-captures` discovery return the same selection/hash; no caller
manufactures old IDs. BranchesClient provides previewGenerationOneCapture,
listGenerationOneCaptures, captureIssuedResource and issuedResourceCaptureStatus.

singular destination preparation requires historicalReviewHash and copies the
EXACT saved selection into Runtime's reservation. discloseTo is the full current
package's source-ref audience. The existing human disclosure review presents all
retired-envelope facts and current facts, reads actual old/current packages,

and budgeted fresh execution/Chat/Step/import/resource maps and canonical current

owner command and final checkpoint readback use existing singular APIs.
