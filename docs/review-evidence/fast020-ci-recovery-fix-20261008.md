## Browser latency failure

Exact-head Verify failed at 408.4 ms against the existing 250 ms isolated API p95 criterion. A local run of the same fixture with observational Playwright network timing reproduced 548 ms, with browser pre-request queue p95 517.186 ms, request-to-headers p95 3.127 ms and Node event-loop p95 10.527 ms (1,600 probe requests). The fixture uses an inert HTTP server, not the product API. Every simulated query fetched the identical URL with default browser cache handling; no mocked endpoint intentionally slept.

A separate 32-request browser experiment with a controlled 15 ms server delay measured header p95 548.2 ms for identical default-cache URLs, 527.3 ms with only a response `Cache-Control: no-store` header, 117.1 ms for unique URLs and 137.5 ms with fetch `cache: "no-store"`. This isolates cache serialization from product server work; the controlled delay is an experimental condition, not a claim about the CI server's delay.

The original storm runner and entry are byte-identical between approved master and integration821. The product stream-rate probe uses `cache: "no-store"` in `apps/web/src/api/real.ts`. Ordinary `requestJson` instead coalesces identical background reads and fetches their actual distinct API paths. The fixture maps dozens of distinct query keys onto one identical probe URL, introducing a cache lock absent from those distinct product endpoints. The legacy `performance-browser.mjs` separately measures real directory endpoints through response-body decoding; it is a different interval and is not substituted for this criterion.

The shared fixture probe now requests `cache: "no-store"`. It retains the original fetch-to-headers 250 ms criterion, validates and consumes the body afterward, and logs browser queue and wire timing separately. No sample is discarded, threshold raised, retry added or assertion skipped. A first response is held until a second identical-URL probe reaches the server: this overlap oracle passes only if the shared probe avoids cache serialization. An external negative-control runner forced the old cache policy for this oracle and failed with HTTP503 before the storm phases, as expected.

The first repaired experiment temporarily measured through response-body consumption and failed at 270.6 ms (queue225.3/wire3.7). That broader interval was corrected to preserve the original header-latency definition before final qualification; its failed log remains retained. This change does not establish production API performance. All original bounded-refresh, hidden-tab, replay, terminal and failed-refresh assertions remain.

## Real recovery coverage

Commit `8dec552152369fae1ac76a79e4a66887c0b3a735` deleted the native speech service/worker/runtime and its sandbox, cleanup-race and recovery suites together. Current speech uses browser APIs. Restoring those obsolete files alone would not test today's runtime. The old recovery workflow was green after Node24 silently selected only two GUI PID tests from its partly missing path list.

Both Release recovery checks and native-beta now use `pnpm test:recovery`, backed by `.github/scripts/check-recovery.mjs`. It explicitly checks every required test/fixture path for a nonempty regular file before starting any child. Its regression removes each required file individually and proves rejection; an empty-file negative path also fails. It sanitizes inherited operator data/broker variables like the existing server test runner and forwards termination signals to its current child.

Required server suites cover provisional/invalid PID identity, explicit coverage-precheck failures, deployment drain of stalled/live browser authority, saved-browser grant handoff and retained cleanup failures/retry, browser residue ownership/birth-marker/forged-PGID/symlink fences, separate-process parent/dependency restart, and abrupt mixed-Branch death without replaying completed effects. Browser suites exercise actual production speech coordinator/hook/components with inert speech/recognition implementations: no provider, speech synthesis endpoint or microphone use. Added checks retain stale end/error callbacks across same-surface playback replacement with throwing cancellation, constructor/playback failure and fresh retry, pagehide cleanup, abandoned dictation callbacks and fresh-generation recovery without sending a message. Existing permission/network/settle-timeout negative paths, exact reply, stable message identity, final-on-pause and late-response fences remain.

The voice runner now resolves the already frozen server `playwright-core` dependency and supports its CommonJS namespace. Linux GitHub runners use the existing disposable Chromium sandbox exception; native non-Linux jobs retain sandboxing. The obsolete bubblewrap/AppArmor setup is no longer invoked for browser-only speech. Its unused inherited script is preserved; no host setup/security changes occurred here. Real native installed, physical microphone/voice and provider/platform proof remain separate gates.
