# Standalone imported Script continuation

The original installation-status reader in `BranchRuntimePackageReview.tsx` mounts `BranchForeignContinuationReview` only after saved standalone runtime data and native receipt match. ExecutionPanel already mounts that reader for imported owners; its existing integration is reused. Tree receipts expose no continuation action.

The user selects an exact original checkpoint key and SHA-256, requests the existing SDK current-authority review, inspects the complete original checkpoint and current definition, bindings, configuration, directory identities, capability policy, budget and native maps, then explicitly consents. Confirm obtains a fresh review and invalidates consent if its digest changed. The backend remains the authoritative first-generation manual/synchronous/serial/effect-free Script family and current-destination gate. Unknown effects, secrets, unsupported families, changed definitions/configuration and denied policy remain held. No filesystem restore or native source-process adoption occurs.

One original command occupies the origin/product/API-prefix/Branch/imported-owner storage slot. Its exact selected checkpoint/hash and review digest are retained in the command. Keeping one owner slot prevents changing selection to bypass an unresolved result. Before the only mutation the component refuses an existing slot, stores the complete command, reads it back and checks exact bytes. Storage exceptions or mismatches block mutation. Lost response or remount exposes only original-key GET. A 404 or unavailable status remains held; it never creates a new key or resubmits. Completed receipts remain retained, preserve the original owner, and require deliberate navigation to the fresh execution.

The actual rendered tree import reproduced a preexisting receipt mismatch: exported configuration contains `secretBindings: {}`, while the canonical installed receipt omits that empty field. The web validator now supplies an empty default on both sides before comparing complete configuration. Every other configuration field and nonempty secret binding must still match. Focused regressions cover both refusals. Backend publication and export guards are unchanged.

The eight changed deliverables are the new component/helper, existing runtime reader and package receipt validator, two new UI fixtures, the existing package-validator fixture, and this document. Backend/tree source and dependency/lock changes are excluded.
