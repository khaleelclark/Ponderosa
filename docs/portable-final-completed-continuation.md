Completed portable final-resource continuation
==============================================

This increment supports bounded executable destinations from retained foreign Branch installations, including repeated export/import of a destination's committed final capture. Focused evidence covers three continuations through four separate stores; it does not qualify every final-resource shape or unlimited generations.

The selected source must be the exact generation-zero automatic final package checkpoint, with the existing v2 final-package intent, intake fence, capture receipt, final-exit evidence, completed Requests and completed frontier. The selected frontier and host cut must equal the final boundary. Only the exactly recorded resource-retirement and completion audit tail is accepted. Joins, late/unknown effects and later executable work remain held.

The package must contain one complete plain Shared working root. Raw passive artifacts, including historical attachments and imported artifact mirrors, are retained and their managed destination bytes are checked before admission. Links, exclusions, separate Git, native Git storage, nested roots, memory, Output roles and encoded artifacts remain held. Captured file bytes and history use the existing staged importer into fresh managed live and recovery roots. Existing roots are not adopted or overwritten. This does not claim full portability for held workspace shapes.

Original Project, Chat, Agent, execution and checkpoint identities remain historical evidence. Schema 0046 extends existing restoration receipts to bind the retained installation and its local held owner without synthetic native source rows. Native receipts and update origins migrate unchanged.

A current operator reviews imported evidence and fresh destinations before admission. Completed Requests produce no activations. The exact remapped completed frontier enters ordinary resource cleanup; its staged Chat/import receipts and six-event audit bind a new destination capture. Automatic final capture retains destination history and working bytes before canonical retirement.

Admission and private-byte capture have a durable interruption boundary. Detail and list responses report capture_pending with restoration disabled until the journal is retained. Exact retry starts capture only when existing custody proves the claim is missing. Failed or ambiguous claims preserve files and remain held. Overlapping retries use the existing exclusive claim; a loser returns only the exact committed Branch receipt after byte verification.

After completed cleanup, the same command returns its verified historical receipt under current local-operator audit access with restoreSupported:false. It does not restore deleted live disclosure scope, revive approval, or repeat work. Changed command hashes conflict.

Focused evidence uses separate stores, actual package capture/export/import, fresh roots, explicit disclosure, physical store reopen at both interruption boundaries, overlapping retries, and a scheduler/resource-service cleanup tick with canonical deletion callbacks. It checks final package/history bytes, preserved recovery files, Request provenance, no Runs/activations, populated 0045 upgrade, pre-0042-shaped native evidence and native composer compatibility. This is not deployment or full production filesystem-cleanup qualification.

Repeated continuation revalidates the exact prior retained installation, committed admission, separate held owner plan, destination acceptance, source custody, Request/update maps and all six restored-prefix audit events. Missing prior evidence or a rehashed changed plan remains held. A prior captured frontier alone is insufficient.

Extended evidence uses explicit runtime-data.v2. Current readers still accept legacy v1, and ordinary native standalone exports remain v1. The preceding v1 reader refuses v2 with its unsupported/invalid runtime-data error rather than interpreting new authority. Compact provenance and manifest-command references retain the original immutable import fact once per owner set, with one-hop references and exact hashes. Large import facts use gzip only when the complete serialized base64 wrapper is smaller. Decoding checks canonical base64, exact raw-byte SHA and UTF-8 bytes, declared decoded length, a per-import and aggregate-per-validation 32 MiB decoded bound before allocation, and the existing generation depth bound. Shared facts reuse decoded and validated data only within the synchronous validation operation. No package size limit is raised.

The real four-store probe reduced runtime-data sizes to approximately 0.49, 0.79, 1.32 and 1.94 MB; exact final-run sizes are recorded in the focused evidence log. This demonstrates a finite usable repeated path, not indefinitely constant-size history. Original captures and all historical data remain retained.

The staged final importer removes only the exact operation-created empty backup directory, identified by the inode issued immediately after its exclusive creation. Nonempty or replaced directories remain untouched and hold admission with an accurate retained-data explanation. Distinct attachment bytes, artifact multiplicity, live/recovery files, no Request replay, final custody and post-cleanup restart are checked at every tested destination.

Import preview and saved readback offer an on-demand prior-history inventory and individual fact reads through the bounded server resolver. Each read is tied to the saved installation, exact outer manifest and selected owner path; it returns no execution authority and does not decompress in the browser. The raw saved wrapper remains available alongside readable original facts.
