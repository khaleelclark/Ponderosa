# Owner-independent group journal audit

This source adds read-only operator access to retained group capture and destination command evidence after the original source owner is unavailable. It does not authorize disclosure to Agents, admission, import, recovery, requeue, package hydration, deletion or reclamation. No tests/checks/build or native/provider execution were performed.

## Discovery and SDK

Existing `GET /api/branches/destination-groups/discovery?kind=captures|admissions&limit=...&cursor=...` and `BranchesClient.discoverDestinationGroups` now add `auditSelection` to each verified original item. Copy this object verbatim. It contains `kind`, `branchId`, `executionId`, the actual persisted `journalKey`, `journalSha256`, `custodySha256`, and the original `commandKey` when retained. Admission selections additionally include `admissionId` and `reservationHash`. A legacy capture without retained plaintext command remains unsupported for ordinary capture commands; its actual raw journal key can still select historical audit evidence. No plaintext command or destination identity is reconstructed from a hash.

`GET /api/lifecycle/destination-groups/journal` accepts those fields as query parameters. `BranchesClient.groupJournalAudit(selection,{signal})` returns a `GroupJournalAuditReadback`. The route inherits the existing local operator origin/capability audit boundary and does not use scoped live Branch ownership or supply a substitute disclosure authorizer.

Every result declares `historical:true`, `currentAuthority:false`, `actionEligible:false`, and `held:true`, including when original objects still exist. The response contains the selected original identity, source-owner presence, journal/evidence hashes, state and the validated capture sources/receipts/disposition or destination resource/full ID/Agent maps, import statuses, owner presence, committed receipt and verified retirement receipt. These are audit projections: private Request bodies, package bytes, raw snapshots, configuration and command payload bodies are not returned. UI should use this method to inspect a discovered record whose scoped current-owner GET fails, and must not use it to enable a mutation. Older servers/items without `auditSelection` cannot supply this audit operation.

## Validation

Selection hashes bind the exact original canonical command row, complete custody inventory and reservation/admission identity. Captures reuse the canonical group intent parser and package receipt verifier. Retained captures reconstruct their original sealed snapshot only from their complete retained snapshot/source/receipt inventory and verify its recorded checkpoint hash; this is byte validation, not reconstruction of a command key or executable eligibility. Any surviving checkpoint/version/binding row must agree. No continuation replay or package read occurs.

Destination audit reuses the canonical admission source, group receipt/map, owner/import, retained graph and immutable retirement readers through a distinct callback-free audit entry. It validates every resource/slot/custody binding, complete ID/Agent/import maps and exact original Project/Chat/Step/owner identity. A present source checkpoint must match the original admission bytes; present owner commands, readiness checkpoints, resource members, imports, Requests, updates, Joins, suspensions, activations and artifacts must agree with the retained receipt. Missing current rows are historical absence, not proof of deletion, terminal drain, current disclosure or action eligibility. The retained canonical graph receipt and original journal/reservation/snapshot/receipt evidence remain mandatory for their respective readbacks. Pending/unknown imports are reported unchanged and held; no state is inferred from absence.

Retired groups use the existing immutable tombstone evidence and canonical evidence-hash verifier, including all original slots/resources. A remaining preserve-only admission must agree with the archived original. Admitted groups are never retired by this reader. Ordinary scoped reads and all existing admission/disclosure authorizers retain their current checks; this audit API is never called by their mutation paths.

Absent, malformed, changed or conflicting original evidence refuses with HTTP 409. A journal updated by capture progress invalidates the old selector: explicitly rediscover rather than silently using new evidence. If owner deletion also removed the original command journal and no original selectable record remains, this API refuses instead of manufacturing one from custody metadata or a reservation. No new retention writer or security apparatus is introduced. Input journal evidence is bounded at 16 MiB; existing 2–32 resource, discovery pagination and retained-evidence bounds remain.

Deferred source fixtures cover partial/retained capture audit after owner loss, exact selector/custody/command conflicts, no writes, current checkpoint corruption, missing journal refusal and unknown held imports. A real Branch/canonical receipt fixture composes discovery and audit, synthetically removes only the source owner, verifies full historical maps and unchanged scoped refusal, and corrupts a non-first import owner and Request map. This synthetic source is not deletion, package or provider qualification.
