# Atomic destination groups

Runtime's host-only group API imports one retained whole coordination cut into 2–32 fresh resource organizations. It uses one admission row, one canonical graph writer, one owner transaction/savepoint, one receipt and final-only activation publication. It never loops independent singular admits. Ordinary actor authorization, immutable original actors/audiences/payloads, native effects and original-audience restoration remain unchanged.

## Host contract

Shared DTOs are in `packages/core/src/coordination-destination.ts`. `CoordinationV3Store` exposes:

- `reserveCoordinationDestinationGroup(input, authority)` → `{admissionId,state,reservationHash}`. Input keeps source Branch/execution/checkpoint/hash, command/operator and explicit effect reconciliation. `resources[]` supplies EACH independent custody receipt and `{projectId,conversationId,executionId,resourceStepId,resourceGeneration}` destination. The returned hash is the normalized stored reservation hash; do not hash the unnormalized input for readback.
- `stageCoordinationDestinationGroupResource(id, sourceChatId, {importPlan,agentMap,artifactMap})` binds ONE actual importer `stage(plan)` receipt before that import's Agent/artifact effects. Every source participant has an explicit source-ref mapping. Every retained runtime artifact has an explicit fresh canonical artifact map plus the actual imported copy receipt. Different imports can stage over several owner transactions; the whole group remains held. Exact slot retry is inert, changed slot retry refuses. The last exact slot assembles the immutable group stage. Nothing is admitted or dispatched by a slot.
- Alternatively, `stageCoordinationDestinationGroup(id, {imports,agentMap,artifactMap})` stages ALL importer reservations together, before ANY mapped Agent exists. `imports` keys are exact source Chat IDs. Do not mix whole-group staging with incremental slots.
- `inspectCoordinationDestinationGroupDisclosure(id, authority)` returns exact whole-cut fact disclosure and all current resource policies for a human preview. As with singular preview, this bounded preview refuses runtime/package artifacts; an artifact-capable host review surface must be supplied before enabling such imports.
- `reviewCoordinationDestinationGroup(id, authority)` binds the whole cut, every custody/owner revision, every explicit import/Agent/artifact map, all current destination policies and fresh artifact metadata, plus human disclosure revision. It returns the exact review hash.
- `admitCoordinationDestinationGroup(id, reviewHash, authority, compose)` creates the whole graph once. `compose(graph)` MUST synchronously finish EVERY import, persist EVERY actual resource/Step/attempt/owner command receipt and return `CoordinationDestinationOwnerReceipt[]`, one per reserved resource. No async/native effect belongs inside this callback. Each owner command's `result_json.coordinationDestination` must equal the exact SAME whole graph receipt. Issued roots are bound exactly once to actual Steps in the corresponding resource Chat. The Runtime verifies actual canonical rows, then rechecks final policy/disclosure authority, marks the whole group admitted and publishes final frontier activations/outbox. Any caught composer/receipt/policy/wake failure rolls back the whole nested savepoint.
- `readCoordinationDestinationGroup(id, reservationHash, authority)` rechecks current disclosure and the exact canonical graph/provenance/Chat/participant/artifact maps, all owner/resource/import/issued-Step receipts, and activation lineage. Exact admission retry uses this path; it never recomposes, reimports or republishes.

All mutations/reviews require the same canonical owner SQLite connection inside an existing transaction. Readback uses a read transaction/savepoint. `CoordinationDestinationGroupAuthority` is exported by `@ponderosa/agents` and intentionally has DISTINCT `requireGroupCustodyAndOwner(fullNormalizedReservation)` and `authorizeGroupDisclosure(wholeCutReview)` callbacks. A legacy singular callback cannot silently approve only the first resource. Both must synchronously prove actual current authority and return a revision. The normalized envelope retains `custody`/`destination` anchors for shared provenance, but **resources is exhaustive authority**, never the first anchor alone. `resolveArtifact` retains the existing independently admitted content/grant contract and receives the actual full mapped fact audience, including any Join owner receiving outcomes.

The human must currently be allowed to read each original private fact AND disclose it to every actual destination recipient. The fact inventory preserves original audience/actor identity and separately names mapped recipients, including Join owners whose outcomes contain the fact. Ordinary access-settings approval and imported grants confer no disclosure authority. Review must cover FINAL import restrictions/policy; a changed second-resource policy invalidates the whole review. Importers must leave their operations preparing/canonical_committed, and output roles held, until the final group composer completes them together. Per-resource `admit` hooks must not finalize independently.

## Holds, provenance and limits

Migration `0039_coordination_destination_group_chats.sql` reserves every source/fresh Chat pair and immutable importer slot, and RESTRICT-pins every original resource-owner execution (including child owners). Shared runtime scope, intake, activation factory/readiness, scheduler lease SQL and public product owner SQL all respect every group Chat/member. Existing singular methods reject group rows, and singular reservations reject group envelopes. Singular DTOs/call signatures remain compatible. The canonical writer adds an exhaustive original Chat → fresh Chat map; shared historical provenance validates it while retaining original authored facts. One shared destination Project is currently required.

Each source Chat and fresh Chat must be distinct within the group, one resource generation per Chat. Resource custody inventories are disjoint and equal captured member inventories. Every source owner must be settled and all current original Requests/effects/providers drained; a current host adapter proves actual custody/owner/whole-tree eligibility. A tree must capture the exhaustive resource inventory across ALL selected owners: incomplete/non-issued-owner resource captures refuse. Cross-resource Join membership/outcomes use the same whole graph map. Request/Join structural participants must still belong to their original resource Chat; outside control participants refuse. Unknown outcomes/recovery chains, expired deadlines, Decision suspensions, secret bindings, communication-owned artifacts and incomplete provenance remain refused. Multiple destination Projects, shared-Chat resource generations and automatic provider/native replay are outside this slice.

Group retirement is deliberately refused by the singular reconciliation hook. Its source pins and Chat/member holds survive failed staging/restarts; only the separate exhaustive group lifecycle protocol below may retire them. No timeout/reimport/reclamation is inferred.

## Branch integration still required

Branch owns exact issued-frontier package capture for EVERY resource, prospective Chat/Project and owner-tree identity reservation, real custody/per-fact disclosure/current-policy human review, importer orchestration, the synchronous whole-group composer and owner-tree acceptance/lifecycle journal. Integration already preserves Branch aa6be267 readiness checks over singular and **every** `resources[*].destination.executionId` until the single group state admits; its synthetic fixtures cover only this fence. Runtime has notified the Branch owner and does not modify BranchStore or the Branch consumer/composer. Keep the existing multi-resource refusal until those pieces are integrated. This source API is not a complete Branch multi-resource product claim.

Deferred source `tests/branches/destination-group-admission.test.mjs` contains three fixtures for cross-Chat whole-cut mapping/final-only wakes/exact replay/revocation; second-resource policy invalidation and incomplete-composer savepoint rollback; and incremental map replay/singular/group-lifecycle refusal. The fixture uses canonical Requests with an inert synthetic multi-resource/custody inventory, including one retained dependency without a Branch-issued root. It is a Runtime boundary fixture, not whole owner-tree/native/provider qualification. Existing singular and retirement regression sources remain present; the latter adds the required group hold schema fixture. No tests/checks/build/types/Node/native/browser/preparation/execution or migrations were run.

Existing package engine integration is usable for the artifact-free private-organization prepared-import subset: use `holdForDisclosure` for each importer, which durably marks it canonical_committed/prepared and releases the same-Project import lock. Do **not** wait for all group imports/human review inside the first import's `beforeAdmit`, because that blocks the next import's Project lock. At final admission, nest `finishDestinationImport(op1, (result1,complete1) => finishDestinationImport(op2, (result2,complete2) => admitCoordinationDestinationGroup(...)))` under one owner transaction. The ONE group composer persists all owners and calls all completion callbacks; after group admission returns, the nested wrappers observe all imports completed and all identities ready. This is nested importer validation, not independent graph admission. The current package hold path refuses roles, memory, artifacts and live working roots; the Runtime DTO/artifact authority does not expand that package-engine support. Broader prepared-import effects remain explicit integration work.

A Branch checkpoint that captures the newly restored historical graph must run AFTER the Runtime admission returns (still inside the SAME outer owner transaction). During `compose`, the graph is staged and its final admission/provenance receipt is not yet available to historical capture. The composer persists required Step/resource/import/owner receipts; subsequent owner checkpoint/acceptance may consume the now-final admission receipt before the outer commit makes outbox work observable. Existing singular Branch checkpoint ordering must not be copied blindly into a group consumer.

Whole-group retirement uses a separate exhaustive operator protocol documented in `lifecycle-reconciliation.md`: `/api/lifecycle/destination-groups/:id/{review,approve,retire,receipt}`. It retains singular group refusal and requires all resource deletion/drain/effect/reference evidence before one durable approval and one canonical group disposition. A single-resource or partial-resource proof cannot release group holds. Group lifecycle source does not qualify the separately implemented Branch group consumer or provider execution.
