# Local memory consuming-package contract

The host integrates the pinned immutable private.6 core archive (SHA-256 790d81ccabd862e956ce323e00a71c5f2c00042f58261138da16d53593923dba). The host owns permissions and provenance; the core owns memory operations. No application journal, recovery or logical receipt framework is supplied.

Configure localMemory with chromaUrl, collectionPrefix, modelDir, and a NEW private stateDirectory outside canonical dataDir. journalDirectory and legacy journal files refuse without opening/migrating/deleting. Fresh policy initialization requires explicit provision:true; subsequent starts validate independent format2 policy principal, canonical data generation and storage/model binding. This policy database stores only independent operator/global-read grants; it is not memory command state. Old format1 journal-bound policy files refuse. No canonical host DB schema changes occur.

Initial fresh provisioning explicitly creates collections for canonical eligible Chats+global. Reopen verifies existing scopes without silently recreating missing collections, even if provision:true remains set. During a running instance, new canonical Chat IDs may be provisioned through the existing lifecycle hook. Concurrent provisioning uses the existing ChromaStorage in-process exclusive queue, outside per-call authority. No owner lock or persistent scope marker replaces the removed journal. A Chat created while this integration was offline whose collections do not exist requires explicit owner provisioning; it is not silently initialized on reopen. Raw unknown/unclassified or foreign-installation rows are excluded, never implicitly shared or adopted.

The six existing tool names now use physical chunk_id, normal version lineage and explicit destination. memoryId, commandKey, expectedRevision, strategy/replace and forged scope/source_type/audience/provenance fields are rejected. There is no exactly-once/idempotency receipt or optimistic logical revision guarantee. Ordinary search-warning receipts are separately keyed by trusted actor/Chat/Run/fence/read-write context, not durable command state. No hidden DM/provider capture occurs.

Source authority is scalar Chroma metadata host_source_authority containing a bounded versioned principal/id/scope/audience/sourceType/provenance/origin record. New bodies/versions are stamped before mutation. Team and same-Agent private audiences remain separate during write reconciliation, including own-private vs team. Unknown/malformed/foreign records do not enter body retrieval or ANN/rerank. Read search can merge authorized chat/global candidates once through the shared core. All list/get/conflict paths use the same authority view; no raw whole-log body read is used. Only authorized affected-source conflict records are fetched. Missing conflict vectors are actual embeddings of authorized reasoning through the shared local pair or existing authorized vectors; no fabricated unit vector is substituted.

HostMemoryRuntime subclasses the public MemoryRuntime and uses a non-emitting declaration to capture its initialized public ChromaStorage field, then substitutes an interface-compatible per-call authority decorator. No MemoryService constructor import or private core property is accessed. All services are still constructed by core.open, and ranking/reconciliation code remains the pinned core. Nested core exclusive calls execute within the outer raw queue without acquiring it twice. The decorator performs no durable transaction/recovery; multiwrite failure can leave partial effects. It intentionally avoids an unguarded compensating callback running after authority revocation. No atomicity is claimed.

Before every read/effect and delivery, the host re-resolves canonical capability/Agent/Chat/Run/fence/cancel/lease/product/grants. A global grant snapshot cannot survive mid-inference revocation. Write-only save may store its supplied fact without reading existing records; update/forget require source-read authority. Agents may write Chat and global memory by default; human memory-write restrictions remain effective before every effect and delivery. Global update/forget require global read permission; global private visibility is unsupported. Operator global routes use browser origin checks and reject Agent capability tokens without requiring an operator login. Host accessTracking is explicitly false: reads do not mutate access counters. Standalone core defaults are unchanged.

Origin provenance is retained across new physical versions; replacement is not exposed. Business conflict/agent self-healing remains the core semantics, not automatic startup repair. The old six-tool host catalog does not gain broad admin/index/backup tools. Unavailable/archive semantics must map to the actual canonical target's lifecycle policy; the saved source has no separate archive column/API, so no fabricated archive schema is introduced.

Synthetic isolated qualification uses disposable state and no provider account. Native platform and installed-app deployment qualification remain separate.

Permission regressions run with `node --import ./tests/shared/workspace-resolution.mjs --test tests/memory/startup-config.test.mjs` after building. Set `PONDEROSA_TEST_CHROMA_BIN` to a local Chroma executable to also run the owned physical-source save/get/update/forget check. That check starts a fresh disposable Chroma root and uses deterministic synthetic embeddings; it verifies permissions, routing, lineage and provenance, not model recall quality. No provider account is used.
