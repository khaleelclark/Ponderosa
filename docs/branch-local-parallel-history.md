# Local parallel resource retry history

This source adds the existing historical consumer to local fork/join and map cuts. The supported bound is one standalone manual owner, one issued resource Step invocation, generations 1–32, freshContext retry policy with original maxAttempts at most 33, ASYNC or SYNC. Runtime's 32-selection and evidence byte bounds still apply. A map can surround the resource only when its actual item count is one and exactly one resource invocation has occurred; multiple resource items/owners remain refused. Other selected Steps must already be completed or failed and have no Request roots. Prepared, leased, running, waiting and unknown sibling effects are refused. Other active/waiting paths are refused as well; joining ancestors and settled siblings retain their exact shared parallel replay.

The shared history validator still requires every actual precleanup producer seal, immutable intake fence, provider exit, native Script exit, package custody, exact failed Request result, prepared retry metadata, and retirement journal/audit prefix. The existing precleanup producer uses that validator for later-generation exit capture as well. Missing original proof is a refusal. The current executable selected/host cut contains only the current resource Request; old generations retain their exact original full envelopes in canonical historicalPartition. The validation-only old/current host union never reaches imports or the graph writer.

The same parallel codec now selects the exact resource for each generation's operation/opening events, binds each opening to its own original attempt/root/Chat, validates failed settlement through the already verified history proof, requires the configured retry/timestamp/budget, and advances resource generation only at the exact retained retirement prefix. Parallel path/step/attempt/fork/map/join replay remains exhaustive. No second graph replay or admission authority exists. The number of consumed attempts and pinned maxAttempts remain unchanged; the accepted resource alone starts its new generation-zero lifetime.

Existing singular prepare, current package read/import, all-facts human review including each old envelope, final current policy, fresh owner acceptance/budget, ONE canonical Runtime admission transaction, immutable nondispatchable historical receipt, post-admit checkpoints and restart readback are reused. Ordinary rewind remains refused. Original actors and audiences remain intact and current maps omit old Agents/Requests/attempts.

Generation-history preview returns server-owned historyKind (`serial` or `local_parallel`). Verified issued capture status and canonical discovery derive that field from the exact saved cut, alongside existing immutable retry-budget evidence. Existing SDK methods receive the shared DTO addition; no manual historical selector or web change is added. An unavailable legacy budget supplies no shape eligibility. A local_parallel result means this exact cut passed the bounded source validators, not general parallel workflow support or live qualification.

Deferred actual ASYNC/SYNC producer-to-destination fixture source covers fork and one-item map generations 1, 2 and 32: failure, configured retry, observed provider exit, seal, Agent/Chat cleanup, retirement, current import/opening/capture, settlement, all-facts approval, rollback, ONE admit, original budget exhaustion and restart readback. Refusals cover missing seal/retirement, stale preview, changed seal frontier, omitted/reordered/aliased/rehashed chain, cross-path resource Step, unrelated prepared sibling, unknown attempt and old/current Request alias. Native/package/provider adapters remain inert. These fixtures have not been run.

Remaining unsupported: multiple resource invocations, multi-item maps, active sibling host effects, called-owner destination consumption, EXIT, recovery, forwarded/unknown/secret/artifact families, missing original proof, generations beyond 32, larger original retry budgets, restored owners with a different attempt/generation offset, and web adoption. No executable/provider/native/filesystem qualification claim is made.
