# Canonical generated hook namespace authority

The generated relative-hook namespace is a native import result, not portable user data. After final native graph, metadata and ownership verification, the fenced importer records its exact namespace/link identities and relative link text through AgentStore.recordGeneratedHookNamespace. The store resolves the local creation operation from exact Agent membership. Regular imports must still be preparing or canonical committed; grouped imports may use a completed per-Chat import only while that exact Branch member remains staged.

Each record binds current Agent/root ownership, root device/inode and retained original SHA. The original must occur in the canonical import artifact identities or a published artifact owned by a current same-root Agent. Shared-root selected members receive independent ownership membership while one physical namespace proof is stored once per operation/root/original. Reporting relationships grant nothing.

Generic creation result updates preserve the canonicalGeneratedHooks marker and cannot introduce or replace it. SQLite keeps it through subsequent receipts and restart. A narrow lookup discovers only a completed local import matching the authorized current Agent, canonical root, currently observed device/inode and verified retained original SHA. Returned values are defensive copies.

The retained reader independently verifies namespace contents, exact declared names/text, every recorded inode fingerprint and expected link hashes. A missing, altered, unknown or ambiguous proof cannot authorize omission. No receipt read from a working folder and no imported operation ID grants authority. Nothing deletes user files or follows a generated target for qualification.

Source regressions cover result replacement/restart, shared-root deduplication, root/SHA mismatch, malformed or conflicting proof, nonstaged completed refusal, and exact grouped staging. No tests, builds or typechecks were executed in this implementation lane.
