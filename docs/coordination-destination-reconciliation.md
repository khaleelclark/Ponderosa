# Staged destination retirement

Host-only API on CoordinationV3Store:

- `reviewCoordinationDestinationReconciliation(id, operatorId, authority)` returns a review hash binding the exact reservation, stage, members, canonical import outcomes, operator and current authority revision/reference inventory.
- `retireCoordinationDestination({admissionId, commandKey, operatorId, expectedReviewHash, releaseSourcePins}, authority)` performs reviewed CAS retirement and returns an immutable receipt.
- `readCoordinationDestinationRetirement(id)` returns that receipt or null, without granting source-content access.

Review and retirement require the same canonical SQLite owner transaction. Retirement uses a nested savepoint. The synchronous authority `inspect({operatorId,reservation,stage})` must verify CURRENT operator access and ownership, including explicit deleted-owner disposition; actual observed provider/process exit; resolved external effects and import outcomes; and exhaustive current Branch/package/capture/restore reference inventory. Return `{revision,references:string[]}`. Exclude only this admission's own RESTRICT pins. Unknown external outcomes refuse; neither terminal scheduler status nor a stop signal proves process exit. The host adapter owns this proof; ordinary operator text cannot supply it. `requireApproval(input,review)` must verify a durable explicit human choice for this exact hash and pin disposition. Runtime re-reads the full evidence after approval; asynchronous callbacks refuse.

The caller must settle import rollback and finish canonical destination Chat/Agent deletion first. Runtime independently refuses surviving Chat membership or live mapped identities (soft-deleted Agent audit rows remain preserved), active/unknown scheduler Runs or activations among mapped members, and any destination creation operation not rolled_back. A staged import requires its actual settled operation row; missing evidence is not success. Abandoned pre-stage reservations can retire only after the host proves no unknown import or effect remains, including effects not yet recorded in the canonical import table.

`releaseSourcePins:true` additionally requires zero external references. Runtime then archives the full immutable admission row, snapshot, member map and review in the retirement receipt table, and removes the obsolete unadmitted admission/member rows in that same transaction. This is the sole safe release path, after evidence and reference proof; it never deletes pins to bypass a live reference. All archived destination Chat/Agent IDs remain dispatch-held. Admission calls and reuse of the original reservation command or Chat identity refuse. The source Branch/execution/checkpoint may subsequently follow its own authorized lifecycle; this method does not delete those objects or any package/artifact bytes.

`releaseSourcePins:false` retires the admission while retaining its source pins. This slice intentionally has no later upgrade/release command. Admitted admissions and their historical provenance pins always refuse retirement. Existing Branch owner commands may retain references: Branch must explicitly reconcile those references before claiming an empty inventory. No automatic timeout, unknown import replay, package reclamation, provider call or lifecycle route is introduced. The integrated host now supplies operator routes and durable approval adapter (see lifecycle-reconciliation.md); Branch owns exhaustive owner/reference evidence. The tombstone retains original private source evidence, so retention/redaction of that audit evidence is a separate future policy, not hidden garbage collection.

Migration `0038_coordination_destination_retirements.sql` is additive and registered once. `tests/branches/destination-reconciliation.test.mjs` contains two deferred focused fixtures for CAS/reference refusal/idempotent immutable tombstones and unknown import/identity/approval-mutation refusal. These use a minimal SQLite boundary fixture, not actual provider or owner-tree drain. No tests, migrations, builds, type checks, Node/native/browser/runner execution have been performed for this slice.
