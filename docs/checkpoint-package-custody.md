# Checkpoint package custody

Selected membership must contain closed organization subtrees, including every selected member's manager and live descendants. Multiple independent complete roots are valid. Unrelated Chat Agents stay excluded. Packaging checks actual topology inside the source boundary (including pending creation); Branch checks its sealed resource generation and creation receipts. Missing/moved members or crossing edges refuse instead of expanding membership or flattening managers.

Future Branch checkpoints can retain private authored history, uploaded originals and scoped memory as an ordinary full portable package. Old metadata-only checkpoints have no recoverable resource cut and remain unsupported.

`BranchPackageEngine.captureCheckpoint(source)` acquires the shared Runtime `beginSourceCapture` token over canonical state and the actual local-memory policy connection. `source` has `checkpointId` (the stable intent reserved BEFORE asynchronous capture), `sourceChatId`, ordered `agentIds`, and `intent:{executionId,resourceStepId,resourceGeneration,frontierSha256,bindingSha256,configurationSha256}`. Generation is a nonnegative safe integer; the three hashes are lowercase SHA256. Branch owns reserving and pinning these values transactionally and finalizing only that same intent. The optimistic boundary rejects any supported SQL or participating filesystem/memory writer crossing the asynchronous export and durable custody commit. Memory readiness/provisioning finishes before capture; active or durable unknown memory writes refuse capture. Package import admission alone does not satisfy this contract. The packaging callback does not acquire nested import admission while exporting individual definitions.

Capture preserves exact ordered source membership and real manager edges within that membership, composing independent reporting roots without invented managers. It returns `CheckpointPackageReceipt`: version 1, durable `custodyId`, all source/intent fields, actual runtime `boundaryId`, `sha256` and UTF-8 `byteLength`. Source membership is checked against package node refs and source Chat refs. A checkpoint identity is immutable: a different membership or intent refuses, an existing valid receipt is returned without source access or recapture, and an interrupted capture refuses a later source cut under that identity.

`inspectCheckpoint(source)` returns `{state:'missing'}`, `{state:'capturing',source,boundaryId}`, `{state:'failed',source,boundaryId,reason}`, `{state:'retained',receipt}` or `{state:'released',receipt}`. Retained inspection verifies bytes before returning the receipt. A changed intent conflicts in every state. Capturing evidence survives interrupted writes; Branch must not dispatch or clean up resources that require a retained capture while capture is missing/interrupted. Existing retained capture lookup precedes Runtime boundary acquisition, so lost-response retries can return the original receipt after source deletion.

`readCheckpoint(receipt)` verifies stored receipt, regular payload, byte limit, length, digest, package schema and source membership. It never consults source Agent/Chat existence. `releaseCheckpoint(receipt)` durably revokes admission before removing payload bytes; repeated release completes interrupted cleanup. Released identities cannot be captured again. Release requires the exact retained receipt and belongs to checkpoint ownership, never source deletion.

The host-only `checkpoint-package-custody` directory is independent of `agent-import-operations`. Payloads and receipts use private permissions, bounded existing package serialization/parser, file fsync, atomic rename and directory fsync where supported. A pending receipt is written before source export. Source counters/epochs, actual membership and memory eligibility are revalidated under synchronous IMMEDIATE transactions on all supplied SQL connections; receipt rename and fsync occur synchronously in that admission turn after payload bytes are durable. Runtime supplies the boundary identity. Failed/interrupted capture retains pending evidence and any partial bytes for diagnosis; it never pretends a later recapture is the original cut. Do not apply import-operation cleanup to this directory. Explicit orphan/interrupted capture reclamation is not exposed by this initial contract.

Restore reads retained bytes, then uses existing fresh import with one creation receipt and complete Agent mapping. Never replay an old `accessSettingsResolution`: obtain a new review hash against the actual destination Chat and current policy. Source memory/browser/profile settings remain suggestions requiring destination choices. Source grants, provider sessions, credentials and execution authority are not adopted. This is the portable authored resource inventory, not a provider-native session backup.

Deferred regressions cover restarted read without source lookup, capture idempotence, release tombstones, interrupted capture refusal, changed membership and corrupted bytes. They have not been executed. Runtime writer/deletion integration and external-memory tracking are wired in source. Execution evidence remains deferred; Branch journaling/finalization/rewind consumers must still adopt this API before resource restoration is available.

Memory mutation calls use the existing authority collection APIs through tracked method views: collection create/delete and all put/update/remove/conflict/import/rollback/purge writes register before the remote call. Each write durably installs a private `source-mutation-holds` record in the configured memory policy directory, removing it only after success and durable cleanup. Any failure remains conservatively held; capture checks those holds even after restart. These holds contain no source content or credentials and do not replay remote writes. Explicit backend reconciliation/hold reclamation is outside this API; preserving an unknown hold can block future captures until reconciled. Existing memory calls retain their source authority checks and normal error behavior.
