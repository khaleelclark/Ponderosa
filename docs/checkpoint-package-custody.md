# Checkpoint package custody

Future Branch checkpoints can retain private authored history, uploaded originals and scoped memory as an ordinary full portable package. Old metadata-only checkpoints have no recoverable resource cut and remain unsupported.

`BranchPackageEngine.captureCheckpoint({checkpointId,sourceChatId,agentIds})` requires the host's `withCheckpointSourceBoundary(source, work)` admission. The boundary must cover every relevant source writer and deletion for the entire asynchronous export and durable custody commit. An absent boundary refuses capture. Package import admission alone does not satisfy this contract. The packaging callback does not acquire nested import admission while exporting individual definitions.

Capture preserves exact ordered source membership and real manager edges within that membership, composing independent reporting roots without invented managers. It returns `CheckpointPackageReceipt`: version 1, checkpoint identity, source Chat, ordered source Agent IDs, boundary identity, SHA256 and UTF-8 byte length. Source membership is checked against package node refs and source Chat refs. A checkpoint identity is immutable: a different membership refuses, an existing valid receipt is returned without recapture, and an interrupted capture refuses a later source cut under that identity.

`readCheckpoint(receipt)` verifies stored receipt, regular payload, byte limit, length, digest, package schema and source membership. It never consults source Agent/Chat existence. `releaseCheckpoint(receipt)` durably revokes admission before removing payload bytes; repeated release completes interrupted cleanup. Released identities cannot be captured again. Release requires the exact retained receipt and belongs to checkpoint ownership, never source deletion.

The host-only `checkpoint-package-custody` directory is independent of `agent-import-operations`. Payloads and receipts use private permissions, bounded existing package serialization/parser, file fsync, atomic rename and directory fsync where supported. A pending receipt is written before source export. Failed/interrupted capture retains pending evidence and any partial bytes for diagnosis; it never pretends a later recapture is the original cut. Do not apply import-operation cleanup to this directory. Explicit orphan/interrupted capture reclamation is not exposed by this initial contract.

Restore reads retained bytes, then uses existing fresh import with one creation receipt and complete Agent mapping. Never replay an old `accessSettingsResolution`: obtain a new review hash against the actual destination Chat and current policy. Source memory/browser/profile settings remain suggestions requiring destination choices. Source grants, provider sessions, credentials and execution authority are not adopted. This is the portable authored resource inventory, not a provider-native session backup.

Deferred regressions cover restarted read without source lookup, capture idempotence, release tombstones, interrupted capture refusal, changed membership and corrupted bytes. They have not been executed. Runtime writer/deletion fence integration is required before claiming checkpoint-consistent capture is available.
